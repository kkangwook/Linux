 / 루트
│
├─ /home : 일반 사용자의 개인 파일과 설정이 저장되는 디렉토리
│  ├─ /home/$USER : 현재 사용자의 홈 디렉토리 → ex) cd "$HOME" (홈 디렉토리로 이동), ls -la "$HOME" (숨김 파일까지 확인)
│  ├─ ~/.bashrc : Bash 환경변수·PATH·alias 설정 파일 → ex) grep "PATH" ~/.bashrc (PATH 관련 설정 확인), source ~/.bashrc (수정 내용 적용)
│  └─ ~/.ssh : SSH 키와 접속 설정 디렉토리 → ex) ls -la ~/.ssh (SSH 관련 파일 확인), less ~/.ssh/config (SSH 접속 설정 확인)
│
├─ /etc : 운영체제와 서비스의 설정 파일이 저장되는 디렉토리
│  ├─ /etc/passwd : 사용자 계정 정보 → ex) grep "^${USER}:" /etc/passwd (현재 사용자 계정 정보 가져오기)
│  ├─ /etc/group : 사용자 그룹 정보 → ex) groups "$USER" (현재 사용자가 속한 그룹 확인), grep "^sudo:" /etc/group (sudo 그룹 정보 확인)
│  ├─ /etc/shells : 사용 가능한 로그인 셸 목록 → ex) cat /etc/shells (사용 가능한 셸 확인)
│  ├─ /etc/hosts : 호스트명과 IP 주소의 수동 연결 정보 → ex) cat /etc/hosts (등록된 호스트명과 IP 확인)
│  ├─ /etc/hostname : 현재 서버의 호스트명 → ex) cat /etc/hostname (서버 호스트명 확인)
│  ├─ /etc/resolv.conf : DNS 서버 설정 → ex) cat /etc/resolv.conf (사용 중인 DNS 서버 확인)
│  ├─ /etc/os-release : 리눅스 배포판 정보 → ex) cat /etc/os-release (Ubuntu·Rocky 등 배포판과 버전 확인)
│  ├─ /etc/services : 서비스명과 대표 포트 번호 대응표 → ex) grep -E "^(ssh|http|https)[[:space:]]" /etc/services (SSH·HTTP·HTTPS 포트 확인)
│  ├─ /etc/fstab : 부팅할 때 자동으로 연결할 디스크 설정 → ex) cat /etc/fstab (자동 마운트 설정 확인)
│  └─ /etc/ssh/sshd_config : SSH 서버 설정 → ex) grep -Ev '^[[:space:]]*(#|$)' /etc/ssh/sshd_config (주석·빈 줄을 제외한 SSH 설정 확인)
│
├─ /usr : 설치된 명령어와 프로그램 라이브러리가 저장되는 디렉토리
│  ├─ /usr/bin : 일반 사용자가 사용하는 명령어 → ex) command -v grep (실행되는 grep의 위치 확인), ls /usr/bin | less (명령어 목록 확인)
│  ├─ /usr/sbin : 시스템 관리용 명령어 → ex) command -v useradd (useradd 명령어 위치 확인)
│  ├─ /usr/lib : 프로그램이 사용하는 라이브러리 → ex) ldd /usr/bin/grep (grep이 사용하는 공유 라이브러리 확인)
│  └─ /usr/local/bin : 직접 설치한 명령어와 사용자 스크립트 → ex) ls -l /usr/local/bin (직접 설치된 명령어 확인)
│
├─ /bin : 필수 일반 명령어가 위치하던 디렉토리이며 현재는 /usr/bin의 심볼릭링크 (sbin/lib도 각각 usr의 소프트링크)
│  └─ /bin/bash : Bash 셸 프로그램 자체 → ex) /bin/bash --version (Bash 버전 확인), readlink -f /bin/bash (실제 파일 위치 확인)
│
├─ /var : 로그와 같이 실행 중 계속 변경되는 데이터가 저장되는 디렉토리
│  ├─ /var/log : 시스템과 애플리케이션 로그 → ex) ls -lh /var/log (로그 파일 목록 확인), tail -f /var/log/syslog (시스템 로그 실시간 확인)
│  ├─ /var/lib : Docker·DB 등 프로그램의 상태 데이터 → ex) sudo du -sh /var/lib/* (프로그램별 데이터 용량 확인)
│  ├─ /var/cache : 프로그램이 다시 생성할 수 있는 캐시 → ex) sudo du -sh /var/cache/* (캐시별 용량 확인)
│  └─ /var/tmp : 재부팅 후에도 남을 수 있는 임시 파일 → ex) ls -la /var/tmp (임시 파일 확인)
│
├─ /proc : 실행 중인 프로세스와 커널 정보를 보여주는 가상 디렉토리
│  ├─ /proc/cpuinfo : CPU 상세 정보 → ex) grep "^model name" /proc/cpuinfo (CPU 모델명 확인), lscpu (CPU 정보 요약)
│  ├─ /proc/meminfo : 메모리 상세 정보 → ex) grep -E "MemTotal|MemAvailable" /proc/meminfo (전체·사용 가능 메모리 확인), free -h (메모리 사용량 요약)
│  ├─ /proc/version : 실행 중인 커널 정보 → ex) cat /proc/version (커널 상세 정보 확인), uname -r (커널 버전 확인)
│  ├─ /proc/uptime : 서버가 부팅된 후 지난 시간 → ex) uptime (서버 가동 시간과 부하 확인)
│  └─ /proc/PID : 해당 PID 프로세스의 실행 정보 → ex) cat /proc/1234/status (PID 1234 상태 확인), readlink -f /proc/1234/exe (실행 파일 확인)
│
├─ /dev : 디스크·터미널 같은 장치를 파일 형태로 나타내는 디렉토리
│  ├─ /dev/sda·/dev/nvme0n1 : 서버의 디스크 장치 → ex) lsblk -f (디스크·파티션·파일시스템 확인)
│  ├─ /dev/tty : 현재 터미널 장치 → ex) tty (현재 사용 중인 터미널 확인)
│  └─ /dev/null : 전달된 출력을 버리는 특수 장치 → ex) find /etc -name "*.conf" 2>/dev/null (권한 오류를 숨기고 설정 파일 검색)
│
├─ /run : 현재 부팅 중인 서비스의 PID·소켓 등 실행 정보
│  └─ /run/*.pid : 실행 중인 프로그램의 PID 파일 → ex) find /run -name "*.pid" 2>/dev/null (PID 파일 검색)
│
├─ /tmp : 작업 중 잠시 사용하는 임시 파일
│  └─ /tmp : 재부팅이나 정책에 따라 파일이 삭제될 수 있음 → ex) mktemp -d (안전한 임시 디렉토리 생성), ls -la /tmp (임시 파일 확인)
│
├─ /mnt : 관리자가 외부 디스크나 파일시스템을 임시로 연결하는 위치
│  └─ /mnt : 직접 마운트한 파일시스템 접근 → ex) findmnt (현재 마운트 상태 확인), df -h (파일시스템별 용량 확인)
│
├─ /media : USB 같은 이동식 장치가 자동 연결되는 위치
│  └─ /media : 자동 마운트된 이동식 장치 접근 → ex) ls -la /media (연결된 이동식 장치 확인)
│
└─ /opt : 독립적으로 배포되는 외부 프로그램의 설치 위치
   └─ /opt/프로그램명 : 외부 프로그램별 설치 파일 → ex) ls -la /opt (설치된 외부 프로그램 확인)

	Gateway주소도 10.0.2.1 ~ 10.0.2.254안에 있어여 함 ex) 10.0.2.2

	ip: 기기간 식별주는 번호

-find		find <어디서부터 찾을지> <어떤 기준으로 찾을지> <표현식>  -> 파일하나하나 출력
	ex) find /var/log -name "*.log"    <- find가 특수한 경우라 ""안에!!!!!!
	옵션: -name, -type f/d(file or dir), -size +-10M, -user
	-검색 결과에 대한 명령 실행: 
		find . -name 'test*' -exec ls -a \;     =>    test*를 찾은 후 추가로 ls-a로 명령하고\;로 끝마침
	-exec에 {}도 들어갈수있는데 이는 find로 찾은애들이 {여기안에} 들어간다고 보면됌
		find /etc -name "hosts" -exec cp {} ~/guests/ \;       =>      find 명령으로 /etc 디렉터리에서 hosts 파일을 찾아 ~/guests로 복사

# -exec대신 | 써도 돼지만 {}못써 인자 자체를 못받아오고 ls, less같은 기초 명령문만 사용가능
# or var=$(find~)로 저장도 가능

-echo			echo <옵션> '내용'
	입력받은걸 출력 -> 문자열, 변수등 (파일은 안보여줌!!!!!-> cat사용)
	echo "hi"    ->   hi출력
	echo "hi" > echo.txt    ->   hi로 덮어씌움
	echo "hi" >> echo.txt      ->   이어쓰기
	-n 메시지 출력 후 newline 문자를 추가하지 않는다.
	-e backslash escapes문자를 해석하여 특별한 의미를 지정한다. (\t, \n,\a)

-cat		cat <옵션> <파일>
	cat file1 file2	-> 여러 파일 출력
	cat > file1 		->  파일 열리고 안에 입력하고 ctrl+d로 저장
	cat >> file1	-> 이어쓰기
	cat -n으로 행번호 보기가능

-sed		sed <옵션> <명령> <파일이름>   -> sed에서 모든 -e의 실행들은 마지막에 오는 파일에만 실행!!!!!

	sed -n -e '1,$p' sample    -> 만약 여기서 ""이었으면 $p를 변수로 입력 -> 그냥 1,$p값 그대로 sed에 넣기위해 ''사용!!!!!!
	-n: 중복해서 출력하지마라 (pattern sapce꺼 출력하지마라, output만 보여줘라)
	-e: 이 뒤에 명령문올거다
	1: 첫번째줄
	,
	$: 마지막줄
	p: print

	-e '/010/p' : 010이 포함된 모든 행을 출력하라

	sed -n -e '/5555$/r add' -e '1,$p' sample
	-> 마지막($)이 5555가 포함된 행에 add파일을 더해라(r) 그리고실행하라(-e) 첫번째줄부터 끝까지 pring해라 sample파일을

	sed -i -n -e 's/[Mm]$/Male/g' -e 's[Ff]$/Female/g' -e 's/Bob/Mom/g' -e '1,$p' sample
		i=inplace, s=subsititute, g는 global: 한 줄에서 조건에 맞는 모든 문자열을 치환

-awk			awk '조건 { 실행할 명령 }' 파일	
	행=레코드, 열=필드형태 	: 전체=$0, 1열=$1, 2열=$2 ..... n열 $n
	awk ‘{ print “Name:”$1, “Num:”$2 }’ sample		-> ''그대로 awk가 받아가야해서,  출력하려는 고정문자열은 " "로 감쌈
	awk ‘$2 > 20 { print $0}’ sample			-> 조건문도 가능
	awk ‘{ sum += $3} END { print “SUM : “sum}’ sample     -> awk에서 변수들 초기값은 전부 0 -> 지정하고 싶으면 awk 'BEGIN { sum=0 } { sum += $3 } END { print "SUM:", sum }' sample
		-> END는 모든 행을 처리한 다음 한 번 실행되게함 -> 그냥 print하면 루프마다 나오지만 end하고 print하면 마지막 결과만 print	
		-> 최종버전: awk 'BEGIN { sum=0 } $2 > 20 { sum += $3 } END { print "SUM:", sum }' sample
	vi awkp.script하고 안에 c언어 함수만들고print -> awk -f awkp.script sample  하면 script안의 함수를 sample에 적용(f옵션은 file로 script적용시키고 싶을때 사용)

foreground/background 
	Foreground는 현재 터미널을 차지하고 실행되는 프로세스 -> sleep100하면 100초간 터미널에서 암것도 못함
	sleep 100 &	-> 명령 뒤에 &를 붙이면 Background에서 실행 -> 내 터미널에서는 계속 가능
	즉 백그라운드는 뒤에서 실행되는 여러 프로세스
	-> ps aux | grep sleep으로 어떤 pid인지 확인 가능

signal: 실행 중인 프로세스에게 보내는 제어 메시지   : 종료!, 멈춰! 계속!
	ex)
	Ctrl+C
	→ SIGINT 전달
	→ 실행 중인 foreground 프로세스를 보통 종료

	Ctrl+Z
	→ SIGTSTP 전달
	→ foreground 프로세스를 일시정지

	Ctrl+D
	→ 시그널이 아님!
	→ EOF(입력 끝)를 전달
=> 주로 foreground한테 !!!!!!!

-kill		kill <-signal> pid번호
	주로 백그라운드!!! 프로세스처럼 키보드로 Ctrl+C를 바로 보내기 어려운 프로세스에는 PID를 이용해 시그널을 보내는 법
	ex) kill -SIGKILL 1234
	     kill -9 1234		=> 이 둘은 같음
	
	예시)
	1$ bash
	1$ more /etc/services   => more로 보는중에 터미널2로
	2$ ps -a | grep more 	=> 프로세스중 more포함된것만 grep해오기 => 이게 pts0!!!!
	2$ ps -a | grep pts/0	=> 하면 나옴 => 여기에 PID값도 포함
	2$ kill PID			=> 해당 PID번호로 죽임
	2$ kill -9 PID		=> 안죽으면 9옵션으로
	
	옵션
	1  = SIGHUP   : 터미널 연결 종료 / 설정 다시 읽기에 사용되기도 함
	2  = SIGINT   : 인터럽트 → Ctrl+C와 동일
	9  = SIGKILL  : 강제 종료 (프로세스가 무시할 수 없음)
	15 = SIGTERM  : 정상 종료 요청 → kill의 기본값

-redirection
	방향은 원래 키보드 -> 프로세스 -> 모니터
	리디렉션0 으로 파일 -> 프로세스	(<   : 키보드 대신 파일에서 입력받기)
	리디렉션1 로 프로세스 -> 파일
		>   : 정상 출력을 파일에 저장 (기존 내용 덮어쓰기) ex) cat > file
		>>  : 정상 출력을 파일 끝에 추가  ex) cat >> file
	리디렉션2로 프로세스의에러(출력) -> 파일 (에러 출력방향 변경)
		2>  : 에러 출력을 파일에 저장  ex) ls /없는경로 2> error.txt        
		2>> : 에러 출력을 파일 끝에 추가
		즉 출력하되 에러 메시지는 버린다!!!!!!
